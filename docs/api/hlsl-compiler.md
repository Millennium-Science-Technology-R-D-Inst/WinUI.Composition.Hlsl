# HlslCompiler class

Compiles public HLSL contracts to Composition-compatible FXC SM4 shader-linking DXBC without creating Composition/XAML objects.

**Namespace:** `WinUI.Composition.Hlsl`  
**Package:** `WinUI.Composition.Hlsl` v1.0.0

## CompileAsync

```csharp
public static IAsyncOperation<HlslShaderLibrary> CompileAsync(
    string shader,
    HlslEffectKind kind,
    HlslShaderProfile profile);
```

The method copies/validates the request on entry, resumes on a background thread, generates the same ABI wrappers used by the build target, and invokes `D3DCompile`. The returned `HlslShaderLibrary` owns the resulting DXBC.

## CompileWithPropertiesAsync

```csharp
public static IAsyncOperation<HlslShaderLibrary> CompileWithPropertiesAsync(
    string shader,
    HlslEffectKind kind,
    HlslShaderProfile profile,
    IReadOnlyList<HlslFloatProperty> properties);
```

Adds `UserConstants` declarations matching the public scalar-property ABI before compilation.

## Shader contracts

| Kind | User-authored function |
| --- | --- |
| `Color` | `float4 PSBody(float4 color)` |
| `Sampler` | `float4 Shade(float2 uv, float4 samplerDataExt)` |
| `MaterializedSampler` | `float4 Shade(float2 uv, float4 samplerDataExt, float4 samplerData)` |

Sampler edge-mode exports and the materialized identity helper are generated by the library. Applications should not hand-maintain those private wrapper names.

## Threading and performance

The asynchronous compiler performs CPU/FXC work only. It does not create a `Compositor`, XAML object, brush, native effect factory, or install the private Composition adapter from the background thread.

For shaders known at build time, `<HlslCompositionShader>` remains the preferred production path because compilation failures become MSBuild errors and no runtime compilation is required. `CompileAsync` is intended for runtime-generated shaders, tooling, development, and cache warm-up.
