# Get started with WinUI.Composition.Hlsl

This article takes a WinUI 3 application from package installation to a running custom Composition shader. It uses the build-time shader path, which is the recommended production path because HLSL syntax, entry-point shape, shader profile, and generated metadata are validated during the build instead of at first render.

## Prerequisites

- A WinUI 3 desktop project using Windows App SDK 1.6 or later.
- A Windows SDK that contains `fxc.exe`.
- x86, x64, or ARM64.
- C++/WinRT or C#/.NET 8.

The NuGet package has a minimum Windows App SDK dependency of 1.6. The package does not require Windows App SDK 2.4.

## Install the package

Add the package to the application project:

```xml
<ItemGroup>
  <PackageReference Include="WinUI.Composition.Hlsl" Version="1.0.0" />
</ItemGroup>
```

The package imports its shader build targets transitively.

## Create a shader

Create `Effects/Invert.hlsl`:

```hlsl
export float4 PSBody(float4 color)
{
    return float4(color.a - color.rgb, color.a);
}
```

This is a `Color` effect. `PSBody` receives the input pixel and returns the output pixel.

Add the shader to the project:

```xml
<ItemGroup>
  <HlslCompositionShader Include="Effects\Invert.hlsl" />
</ItemGroup>
```

`Kind=Auto`, `Profile=Pixel40`, and `SourceCount=1` are the defaults. The build target asks FXC to compile a linkable `lib_4_0*` shader library, not a standalone `ps_5_0` pixel shader.

## Use the shader from C++/WinRT

Native projects generate a `.g.h` file and embed the compiled DXBC bytes in the application by default.

```cpp
#include "Invert.g.h"

import winrt.WinUI.Composition.Hlsl;

using namespace winrt;
using namespace winrt::Microsoft::UI::Composition;
using namespace winrt::WinUI::Composition::Hlsl;

auto effect = HlslEffect::CreateCompiledFromGeneratedByteArray(
    {}, g_Effects_Invert_Shader);

auto brush = HlslComposition::CreateBackdropBrush(compositor, effect);
```

`CreateBackdropBrush` creates a `CompositionBackdropBrush` and binds it to the effect's source. To supply a different brush, create a factory/brush and call `SetSource`, or use `CreateBrushWithSources` for ordered multi-source effects.

## Use the shader from C#

Managed projects publish generated DXBC under the application `Hlsl` content directory.

```csharp
using WinUI.Composition.Hlsl;

var library = await HlslShaderLibrary.LoadGeneratedFromApplicationUriAsync(
    new Uri("ms-appx:///Hlsl/Effects/Invert.dxbc"));

var effect = HlslEffect.CreateCompiled(Guid.Empty, library);
var brush = HlslComposition.CreateBackdropBrush(compositor, effect);
```

Generated DXBC is self-describing. The library recovers its effect kind, profile, and source count from package metadata, so application code does not repeat those values.

## Use a sampling shader

A linked `Sampler` receives normalized coordinates and sampler metadata. Texture/sampler resources are generated by the package.

```hlsl
float4 Shade(float2 uv, float4 samplerDataExt)
{
    float2 texel = samplerDataExt.zw;
    float4 center = texture0.Sample(sampler0, uv);
    float4 right = texture0.Sample(sampler0, uv + float2(texel.x, 0));
    return lerp(center, right, 0.5f);
}
```

You do not declare `texture0` or `sampler0`. The build front end declares them with deterministic register bindings.

## Use multiple linked sources

Declare the number of ordered inputs at build time:

```xml
<HlslCompositionShader Include="Effects\Blend.hlsl">
  <SourceCount>2</SourceCount>
</HlslCompositionShader>
```

Shader:

```hlsl
float4 Shade(
    float2 uv0, float4 samplerDataExt0,
    float2 uv1, float4 samplerDataExt1)
{
    float4 a = texture0.Sample(sampler0, uv0);
    float4 b = texture1.Sample(sampler1, uv1);
    return lerp(a, b, 0.5f);
}
```

The ABI is ordered:

| Source index | Texture | SRV register | Sampler | Sampler register |
| ---: | --- | --- | --- | --- |
| 0 | `texture0` | `t0` | `sampler0` | `s0` |
| 1 | `texture1` | `t1` | `sampler1` | `s1` |
| n | `textureN` | `tN` | `samplerN` | `sN` |

Bind source brushes in the same order with `HlslComposition.CreateBrushWithSources`.

## Add animatable properties

Declare the property schema when creating the effect. The schema is shared by source compilation, precompiled validation, native property updater metadata, and brush setters.

```cpp
auto defaults = single_threaded_vector<float>({ 1.0f, 0.0f });
auto offset = HlslProperty(L"Offset", HlslPropertyType::Vector2, defaults.GetView());
```

Use the matching setter:

```cpp
brush.SetVector2(L"Offset", { 8.0f, 4.0f });
```

Supported types are `Scalar`, `Vector2`, `Vector3`, `Vector4`, `Matrix3x2`, and `Matrix4x4`.

## Choose build-time or runtime compilation

Use build-time `<HlslCompositionShader>` for application-owned shaders known before deployment. It gives the shortest startup path and catches authoring errors in MSBuild.

Use `HlslCompiler` when shader text is generated, downloaded, edited by a user, or otherwise unavailable at build time. Compilation runs asynchronously. Cache `HlslShaderLibrary.Bytecode` if the same generated shader will be reused.

Runtime compilation is not required for ordinary packaged shaders.

## Performance model

The package is designed so validation and compilation stay away from the render hot path:

- FXC compilation is normally a build-time operation.
- Generated-library reflection happens when a library is loaded/created, not per frame.
- Effect factory creation is a setup operation; reuse factories and brushes when practical.
- Property updates use Composition property/updater paths and do not recompile HLSL.
- `GetRuntimeCapabilities()` is side-effect free and does not install or probe the private adapter.

Do not call shader compilation or library loading every frame. Keep `HlslShaderLibrary`, `HlslEffect`, factories, and brushes at the same lifetime granularity you would use for normal Composition resources.
