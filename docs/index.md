# WinUI.Composition.Hlsl documentation

`WinUI.Composition.Hlsl` turns custom HLSL into Windows Graphics Effects / `Microsoft.UI.Composition` nodes and bridges the resulting Composition brushes back to WinUI 3 XAML.

## Recommended production path

```xml
<PackageReference Include="WinUI.Composition.Hlsl" Version="1.0.0" />

<HlslCompositionShader Include="Effects\Glass.hlsl" />
```

`Kind` defaults to `Auto`, `Profile` to `Pixel40`, and `SourceCount` to `1`. For linked multi-source `Color`/`Sampler`, set `SourceCount` from 1 through 16.

Native C++ consumers generate an embedded `.g.h` by default; managed consumers deploy self-describing DXBC under `Hlsl\...`. Generated bytecode records resolved Kind/Profile/SourceCount and is defensively reflected when loaded.

## Current shader contracts

- `Color`: one-source `PSBody(float4)` or multi-source `Shade(float4 color0, ...)`.
- `Sampler`: `Shade(uv, samplerDataExt, ...)`, 1-16 ordered linked sources.
- `MaterializedSampler`: `Shade(uv, samplerDataExt, samplerData)`, exactly one materialized source today.

For samplers, logical source index `i` maps deterministically to `texture{i}:register(t{i})` and `sampler{i}:register(s{i})`. Build integration reflects the generated library and validates these bindings.

## Typed properties

`HlslProperty` supports `Scalar`, `Vector2`, `Vector3`, `Vector4`, `Matrix3x2`, and `Matrix4x4`. Source effects, runtime compilation, native property metadata, constant-buffer packing, and precompiled reflection validation share the same schema. Matrix backing storage is packed as contiguous float components and reconstructed in generated HLSL.

## Public capability boundary

Released Windows App SDK 1.6-2.4 have been runtime-tested on x86 and x64. ARM64 remains experimental until real-device validation is complete. This is a tested range, not a forward-compatibility guarantee for the private Composition ABI.

Currently public:

- x86/x64 Composition graph nodes and single-source materialized lowering;
- linked 1-16 source `Color`/`Sampler`;
- scalar/vector/matrix typed properties;
- build-time and runtime shader compilation;
- C++ embedded and C# loose-DXBC delivery.

Still fail-closed as public contracts:

- multi-source `MaterializedSampler`;
- multiple custom HLSL nodes in one lowered graph;
- arbitrary native nodes after a custom materialized pass.

The runtime contains exploratory multi-pass code for some of these graph shapes, but `HlslRuntimeCapabilities` keeps them false until graph topology, bounds/input mapping, and runtime behavior are validated.
